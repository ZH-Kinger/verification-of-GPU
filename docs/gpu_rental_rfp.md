## 第一章 总则

### 1.1 项目概述

采购人拟租赁 GPU 算力集群与配套存储服务，用于 VLA（Vision-Language-Action）
与 world model 两类模型的分布式训练。

本项目的负载特征与常规大语言模型训练不同，供应商应在方案设计中予以考虑。
训练数据以视频与图像帧为主，文件数量大、单文件小、随机读比例高，存储的瓶颈
在元数据处理与聚合读带宽而非容量；单步计算轻而数据吞吐重，供给不足会直接
拉低 GPU 利用率；序列长、批量大，对单卡显存容量敏感；单次训练周期以周计，
有效训练时间占比较峰值算力更具决定性。

### 1.2 编制依据

采购人《GPU 服务器验收标准》及配套的自动化验收工具链、NVIDIA HGX 平台
公开技术规格、采购人既有集群的运行经验数据。

### 1.3 适用范围

本文件适用于本项目算力、存储、网络、平台及配套服务的技术与商务应答，
并作为合同技术附件的编制基础。附录 A 所列阈值为逐台验收的判定依据。

### 2.2 NVLink 互联

2.2.1　★ A1（否决性条款）　每节点八颗 GPU 须处于同一 NVLink 域内，
经 NVSwitch 全互联。

2.2.2　判定依据如下，由采购人逐台实测，详见附录 A。

（一）`nvidia-smi topo -m` 中全部 56 个 GPU 对（8×7）显示为 `NV18`，
不得出现 `PIX`、`PXB`、`PHB`、`SYS`、`NODE`；

（二）每卡 NVLink 链路数为 18 条，全部处于 Active 状态；

（三）`nvidia-smi nvlink -e` 的 CRC 与 Replay 错误计数为 0；

（四）P2P 单向带宽 B 系列不低于 750 GB/s、H 系列不低于 345 GB/s，
P2P 时延不超过 5 μs；

（五）八卡 NCCL AllReduce Bus BW，B 系列不低于 800 GB/s、H 系列不低于 350 GB/s；

（六）Fabric Manager 服务处于 active (running) 状态，NVSwitch 全部在位且无降级。

2.2.3　下列形态不予接受，出现任意一种即判定该节点不通过验收且不起租：
PCIe 版 GPU 配合 NVLink Bridge；四加四拆域或其他非八卡单域的 NVLink 分区；
NVSwitch 降级运行；Fabric Manager 未启动或版本与驱动不匹配导致 NVLink 未建链；
已开启 MIG 或 GPU 被虚拟化切分。

上述情形在单卡推理或仅核对 GPU 数量时不会显现，只在八卡张量并行时暴露，
届时设备已进入计费期，故列为否决性条款并在签约前实测验证。

2.2.4　供应商应答时须提供一台样机的 `nvidia-smi topo -m` 完整输出、
`nvidia-smi nvlink -s` 输出，以及八卡 `all_reduce_perf` 的实测记录。

### 2.3 集群网络

#### 2.3.1 组网架构

2.3.1.1　计算网络采用 InfiniBand 或 RoCE v2 均可，但须明确说明采用哪一种
及交换机型号。

2.3.1.2　★ A2　GPU 与计算网卡配比为 1:1，不接受 2:1、4:1。

2.3.1.3　★ A3　计算网络 1:1 无收敛，采用轨道优化的 full fat-tree 组网，
节点内第 i 张网卡接入第 i 组 leaf 交换机。

2.3.1.4　每张计算网卡独占 PCIe 插槽，400 G 网卡须为 Gen5 x16，
800 G 网卡须为 Gen6 x16。Gen5 x16 单向约 504 Gb/s，800 G 端口在 Gen5 插槽下
达不到线速，故供应商须明确网卡所在插槽的 PCIe 代数与位宽。

2.3.1.5　`nvidia-smi topo -m` 中 GPU 与其配对网卡须为 `PIX` 或 `PXB`，
不得为 `SYS`。二者分属不同 CPU socket 时，GPUDirect RDMA 流量须经 UPI 转发，
带宽与时延明显劣化，而 `ibstat` 无异常显示，故须随应答提供拓扑矩阵。

2.3.1.6　GPUDirect RDMA 须可用，`nvidia_peermem` 已加载或 dmabuf 路径打通，
ACS 关闭。

2.3.1.7　存储网络与管理网络须为独立物理网络，存储网不低于 2 × 100 GbE，
管理网含带外 BMC。

#### 2.3.2 网络性能指标

2.3.2.1　时延按跳数分档考核。测试工具 `ib_write_lat`，消息长度 2 Byte，取 P99：
同 leaf 交换机下（一跳）不超过 2.5 μs，跨 leaf 经 spine（三跳）不超过 4 μs，
集群内任意两节点最坏值不超过 10 μs。

2.3.2.2　带宽测试工具 `ib_write_bw -s 65536 -x 3 -q 4 --report_gbits`，
最低要求见表 2-3。

表 2-3　网络带宽最低要求

| 场景 | B300（800 G 口） | H200 / H100（400 G 口） |
|---|---|---|
| 单口 write 带宽 | 不低于 720 Gb/s | 不低于 360 Gb/s |
| 单口 read 带宽 | 不低于 720 Gb/s | 不低于 360 Gb/s |
| GPUDirect RDMA 带宽 | 不低于 700 Gb/s | 不低于 350 Gb/s |
| 整机八口聚合 | 不低于 5.7 Tb/s | 不低于 2.8 Tb/s |

2.3.2.3　采用 RoCE 方案的另须满足：MTU 9000、trust mode 为 dscp、
PFC pause 帧占比低于 0.1%、RX discards 为 0。采用 InfiniBand 方案的免填本项。

#### 2.3.3 跨节点集合通信性能

2.3.3.1　测试命令 `all_reduce_perf -b 512M -e 8G -f 2 -g 1`，每节点八 GPU，
Bus BW 最低要求见表 2-4。节点数按实际交付规模取用，方案甲测至 8 节点，
方案乙测至 16 节点。

表 2-4　跨节点 AllReduce Bus BW 最低要求

| 节点数 | B300 | H200 |
|---|---|---|
| 2 节点 / 16 卡 | 不低于 720 GB/s | 不低于 300 GB/s |
| 4 节点 / 32 卡 | 不低于 700 GB/s | 不低于 290 GB/s |
| 8 节点 / 64 卡 | 不低于 680 GB/s | 不低于 280 GB/s |
| 16 节点 / 128 卡 | — | 不低于 270 GB/s |

2.3.3.2　自 2 节点至最大节点数，Bus BW 衰减不得超过 10%。衰减超限通常表明
存在网络收敛、拓扑设计不当或路由哈希冲突。

2.3.3.3　供应商须提供全量规模的 AllReduce、AllGather、ReduceScatter、AllToAll
实测记录。本项为集群级验收的必测项，建议供应商于交付前自测。

### 2.4 电力、制冷与机房

2.4.1　供应商须说明：单机柜供电上限与可放置的 GPU 节点数；冷却方式为风冷、
冷板液冷或浸没；B300 采用风冷是否可行或须液冷；首批所需机柜数与总配电容量；
扩容一倍规模是否需增加机柜与配电及是否已预留；供电冗余等级、UPS 后备时长、
有无柴发；机房 PUE、所在城市与园区名称；机房等级与相关认证。

2.4.2　参考量级：方案甲 8 节点 B300 按 13 kW/节点估算约 104 kW，
方案乙 16 节点 H200 按 10 kW/节点估算约 160 kW，均不含网络与制冷设备。
最终以供应商实测为准。

### 2.5 软件栈与框架兼容性

2.5.1　操作系统为 Ubuntu 22.04 或 24.04，须提供 root 权限，并允许采购人
自行升级驱动、CUDA 与内核。

2.5.2　GPU 驱动 B 系列不低于 580.105、H 系列不低于 550.54，且全集群版本一致；

### 2.6 稳定性、掉卡与慢节点

同步数据并行下集群产出由最慢的 rank 决定：单节点慢 10%，整集群产出即降约 10%；
掉一张卡，该节点便无法承担八路张量并行。两者的共同点是设备仍可登录、可监控，
不体现为传统意义上的不可用，故本节单独定义、单独计量、单独约定责任。

#### 2.6.1 总体指标

2.6.1.1　有效训练时间占比（Goodput）月度不低于 95%，集群可用率月度不低于 99.5%，
两项的定义与计算方法见 6.1。

2.6.1.2　单次训练在全规模下的最长无故障连续运行时长不低于 72 小时；
故障检测至自动恢复不超过 15 分钟；单卡 MTBF 不低于 20000 卡·小时。

2.6.1.3　热备节点比例不低于 3%，且首批至少配置 1 台。

#### 2.6.2 掉卡

2.6.2.1　采购人认定的掉卡见表 2-5。供应商如有异议，须在应答中明确提出。

表 2-5　掉卡的认定

| 类型 | 判定依据 | 是否计入 |
|---|---|---|
| 完全掉线 | `nvidia-smi` 与 `lspci` 中该卡消失（XID 79） | 是 |
| ECC 不可纠错 | 出现任意 uncorrectable ECC 或双比特错误 | 是 |
| 需重启恢复 | 报 XID 后须重启节点方能恢复 | 是，按次计 |

| NVLink 降级 | 该卡链路数少于 18 条，或与其他卡拓扑不再为 NV18 | 是 |
| 持续降频 | 因硬件原因长期 throttle，性能低于同批次中位数 10% 以上 | 按 2.6.3 处理 |

2.6.2.2　月度掉卡率不超过 0.5%（按卡·月计），掉卡自动检测与隔离不超过 5 分钟。

2.6.2.5　「重启即恢复」计入掉卡；同一张卡月内出现 2 次及以上即判定须更换。

2.6.2.6　★ 掉卡期间的计费（B 级条款）

直至更换完成并通过复验。

#### 2.6.3 慢节点

2.6.3.1　慢节点指各项绝对指标均达标、可通过单机验收、监控显示正常，
但基准性能显著低于同批次其他节点的设备。常见成因与检测手段见表 2-6。

表 2-6　慢节点的常见成因

| 成因 | 特征 | 检测手段 |
|---|---|---|
| 热降频 | 机柜位置、进风温度、风扇故障、导热材料不良 | `clocks_throttle_reasons` 含 thermal slowdown |
| 功率封顶 | 机柜供电不足或 power limit 被下调 | throttle reason 含 power cap |
| PCIe 降级 | 链路运行于 Gen4 或 x8 而非 Gen5/6 x16 | `nvidia-smi -q` 的 link gen 与 width；`lspci -vv` LnkSta |
| NVLink 部分降级 | 链路数不足 18 条但系统未报错 | `nvidia-smi nvlink -s` |
| 网卡异常 | 口速协商至低速、跨 socket、PFC 频繁 pause | `ethtool`、`ibstat`、拓扑矩阵、PFC 计数 |
| CPU 与 NUMA | 频率受限、NUMA 绑定错误、数据加载进程调度不当 | `turbostat`、numactl 绑定检查 |
| ECC 重试 | 大量可纠错 ECC 导致隐性重试 | ECC corrected 计数增量 |
| 存储供给不足 | 该节点存储路径性能低，数据加载受限 | 单节点存储带宽实测 |

2.6.3.2　★ 慢节点的认定标准（B 级条款）

在同一批次、同一测试条件下，某节点的基准性能低于该批次中位数 10% 以上的，
认定为慢节点。基准测试项包括单机八卡 NCCL AllReduce Bus BW、gpu_burn 吞吐、
H2D/D2H 带宽、单节点存储读带宽，任一项触发即成立。

上述判据与采购人验收工具链的同批次横向比对口径一致：不低于中位数 95% 判定通过，
90% 至 95% 之间判定复测，低于 90% 判定不通过。

2.6.3.3　供应商须提供按 rank 的每步耗时分布与通信等待时长分解，
用于定位性能落后的 rank 并区分计算耗时与通信等待。

2.6.3.4　须实施定期基准巡检，频率不低于每周一次，全集群执行同一基准并与
中位数比对，巡检报告提供予采购人。`clocks_throttle_reasons` 须纳入上报指标。

2.6.3.5　慢节点认定后 48 小时内完成整改或更换。逾期未处置的，该节点自认定
之日起停止计费，直至整改完成并复验通过。单月慢节点数不超过在租节点数的 5%。

2.6.3.6　供应商须接受采购人以自有工具认定慢节点，依据见附录 A。

GPU 利用率反映的是有 kernel 在执行的时间占比，降频运行时仍显示 100%。
慢节点以基准性能与同批次中位数的相对值判定，不以利用率为据。

2.6.4.1　自动恢复机制须覆盖下列故障类型，供应商应逐项说明检测手段与处置动作：

（二）显存容量、ECC 状态、功率上限、PCIe 链路代数与位宽；

须经多节点测试验证。

5.1.3.1　★ A7（否决性条款）　供应商须提供不少于四节点、且跨 leaf 分布的
实机测试环境。测试节点须分布于不少于两台 leaf 交换机之下，网络架构须与
正式交付同构，即同交换机型号、同收敛比、同轨道设计。是否与其他租户共享
fabric 须如实说明，见 5.1.4。

测试节点若集中于同一台 leaf 之下，流量一跳直达不经 spine，所得为最优情形，
交付后无法复现。故须在测试前提供测试节点的机柜位与所接 leaf 编号，

故要求不少于四节点。

## 第六章 服务等级协议

通用服务等级协议仅考核设备可用性，而本项目的主要损失中，掉卡与慢节点两类
均不体现为设备不可用。故本章按三项独立指标分别考核，任一指标不达标独立触发
赔偿责任，不相互抵扣。

### 6.1 指标与计算方法

表 6-1　服务等级指标

| 编号 | 指标 | 承诺值 | 统计周期 |
|---|---|---|---|
| SLA-1 | 集群可用率 | 不低于 99.5% | 自然月 |
| SLA-2 | 有效训练时间占比（Goodput） | 不低于 95% | 自然月 |
| SLA-3 | 慢节点比例 | 不超过 5%，且单台处置不超过 48 小时 | 自然月 |

6.1.1　计算方法如下，该公式将写入合同。

```
可用率 = (在租节点·小时总数 − 不可用节点·小时数) ÷ 在租节点·小时总数

  「不可用」包含：节点宕机、无法登录、掉卡（按 2.6.2 口径，掉任意一卡
  即该节点整机不可用）、网络中断、存储不可读写，以及超出约定窗口的
  计划内维护。

Goodput = (T总 − T中断 − T回退 − T慢节点折算) ÷ T总

  T中断      因平台故障导致训练进程终止至重新拉起的时长
  T回退      自最近 checkpoint 重跑所损失的时长
  T慢节点折算 Σ(慢节点存续时长 × 该节点相对中位数的性能差值百分比)
             例：某节点性能低 15%、存续 100 小时，折算为 15 节点·小时
```

6.1.2　供应商须应答是否接受上述指标与计算方法。如有异议，须提出完整的替代公式。

### 7.5 扩容

#### 7.5.1 扩容的物理位置

7.5.1.1　★ A6（否决性条款）　后续全部扩容须与首批部署于同一数据中心节点内。
具体要求：数据中心节点与园区须为同一处，不接受跨机房、跨可用区或跨城市；
机房楼与机房模块须为同一处，如需跨模块须说明模块间的网络路径与时延；
fabric 域须为同一域且与首批之间无收敛；须挂载同一套热存储与冷存储，
不得新建独立存储域；管理平台须为同一集群视图，可作为一个整体提交多机任务。

跨机房的两批设备组不成同一无收敛 fabric，链路带宽与时延较机内互联相差
一至两个数量级，扩容后将构成两个互相独立的小集群，无法承担全规模的单一
训练任务。本条同时约束 7.4：不得为适用补贴政策而将扩容设备部署于首批之外
的区域。

7.5.1.2　供应商须书面承诺并写入合同：首批部署的机房名称与地址；
为扩容预留的机柜位数量、配电容量与 fabric 交换机端口数，均不低于首批同等规模；
预留是否收费（优先免费，如收费须报价并说明可否折抵）；届时该机房无资源的
视为违约，须说明赔偿方式。
