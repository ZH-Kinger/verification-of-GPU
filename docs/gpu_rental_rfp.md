## 第一章 总则

### 1.1 项目概述

采购人拟租赁 GPU 算力集群与配套存储服务，用于 VLA（Vision-Language-Action）
与 world model 两类模型的分布式训练。首批为 64 张 B 系列或 128 张 H 系列，
二选一，后续按需扩容。

负载特征：数据以视频与图像帧为主，文件数量大、单文件小、随机读比例高，
存储的瓶颈在元数据与聚合读带宽而非容量；单步计算轻、数据吞吐重，
供给不足会直接拉低 GPU 利用率；序列长、批量大，对显存容量敏感；
单次训练周期以周计，有效训练时间占比（Goodput）较峰值算力更具决定性。

### 1.2 编制依据

1. 采购人《GPU 服务器验收标准》及配套的自动化验收工具链；
2. NVIDIA HGX 平台公开技术规格；
3. 采购人既有集群的运行经验数据。

### 1.3 适用范围

本文件适用于本项目算力、存储、网络、平台及配套服务的技术与商务应答，
并作为后续合同技术附件的编制基础。附录 A 所列阈值将作为逐台验收的判定依据。

### 2.2 NVLink 互联要求

★ A1（否决性条款）：每节点八颗 GPU 须处于同一 NVLink 域内，经 NVSwitch 全互联。

判定依据如下，由采购人逐台实测，详见附录 A：

1. `nvidia-smi topo -m` 中全部 56 个 GPU 对（8×7）显示为 `NV18`，
   不得出现 `PIX`、`PXB`、`PHB`、`SYS`、`NODE`；
2. 每卡 NVLink 链路数为 18 条，全部处于 Active 状态；
3. `nvidia-smi nvlink -e` 的 CRC 与 Replay 错误计数为 0；
4. P2P 单向带宽：B 系列不低于 750 GB/s，H 系列不低于 345 GB/s；
   P2P 延迟不超过 5 μs；
5. 八卡 NCCL AllReduce Bus BW：B 系列不低于 800 GB/s，H 系列不低于 350 GB/s；
6. Fabric Manager 服务处于 active (running) 状态，NVSwitch 全部在位且无降级。

下列形态不予接受，出现任意一种即判定该节点不通过验收且不起租：

1. PCIe 版 GPU 配合 NVLink Bridge（仅支持两两互联）；
2. 四加四拆域或其他非八卡单域的 NVLink 分区；
3. NVSwitch 降级运行（部分链路不通但系统仍可启动）；
4. Fabric Manager 未启动或版本与驱动不匹配，导致 NVLink 未建链；
5. 已开启 MIG 或 GPU 被虚拟化切分。

注：上述情形在单卡推理或仅核对 GPU 数量时不会显现，只在八卡张量并行时暴露，
届时设备已进入计费期。故列为否决性条款并在签约前实测验证。

供应商应答时须提供一台样机的 `nvidia-smi topo -m` 完整输出、
`nvidia-smi nvlink -s` 输出，以及八卡 `all_reduce_perf` 的实测记录。

### 2.3 集群网络要求

#### 2.3.1 组网架构

| 项目 | 要求 |
|---|---|
| 计算网络 | InfiniBand 或 RoCE v2，须明确说明采用哪一种及交换机型号 |
| ★ A2 配比 | GPU 与计算网卡配比为 1:1，不接受 2:1、4:1 |
| ★ A3 收敛比 | 1:1 无收敛（full fat-tree，轨道优化） |
| 拓扑 | 节点内第 i 张网卡接入第 i 组 leaf 交换机 |
| PCIe | 每张计算网卡独占 PCIe Gen5 x16（400 G）或 Gen6 x16（800 G） |
| GPU 与网卡亲和性 | `nvidia-smi topo -m` 中 GPU 与其配对网卡为 `PIX` 或 `PXB`，不得为 `SYS` |
| GPUDirect RDMA | 须可用（`nvidia_peermem` 已加载或 dmabuf 路径打通），ACS 关闭 |
| 存储网络 | 独立物理网络，不低于 2 × 100 GbE |
| 管理网络 | 独立，含带外 BMC |

注一：Gen5 x16 单向约 504 Gb/s，800 G 端口在 Gen5 插槽下达不到线速，
故须明确网卡所在插槽的 PCIe 代数与位宽。

注二：GPU 与配对网卡分属不同 CPU socket 时，GPUDirect RDMA 流量须经 UPI 转发，
带宽与时延明显劣化，而 `ibstat` 无异常显示。须随应答提供拓扑矩阵。

| 跨 leaf 经 spine（三跳） | 不超过 4 μs | |

带宽测试工具 `ib_write_bw -s 65536 -x 3 -q 4 --report_gbits`：

| 场景 | B300（800 G 口） | H200 / H100（400 G 口） | 供应商应答（实测） |

| 节点数 | B300 | H200 | 供应商应答（实测） |

### 2.6 稳定性、掉卡与慢节点

同步数据并行下集群产出由最慢的 rank 决定：单节点慢 10%，整集群产出即降约 10%；
掉一张卡，该节点便无法承担八路张量并行。两者的共同点是设备仍可登录、可监控，
不体现为传统意义上的不可用，故本节单独定义、单独计量、单独约定责任。

#### 2.6.3 慢节点

慢节点指各项绝对指标均达标、可通过单机验收、监控显示正常，
但基准性能显著低于同批次其他节点的设备。

常见成因及对应的检测手段：

| 成因 | 特征 | 检测手段 |
|---|---|---|
| 热降频 | 机柜位置、进风温度、风扇故障、导热材料不良 | `clocks_throttle_reasons` 含 thermal slowdown |
| 功率封顶 | 机柜供电不足或 power limit 被下调 | throttle reason 含 power cap；`nvidia-smi -q -d POWER` |
| PCIe 降级 | 链路运行于 Gen4 或 x8 而非 Gen5/6 x16 | `nvidia-smi -q` 的 link gen 与 width；`lspci -vv` LnkSta |
| NVLink 部分降级 | 链路数不足 18 条但系统未报错 | `nvidia-smi nvlink -s` |
| 网卡异常 | 口速协商至低速、跨 socket、PFC 频繁 pause | `ethtool`、`ibstat`、拓扑矩阵、PFC 计数 |
| CPU 与 NUMA | 频率受限、NUMA 绑定错误、数据加载进程调度不当 | `turbostat`、numactl 绑定检查 |
| ECC 重试 | 大量可纠错 ECC 导致隐性重试 | ECC corrected 计数增量 |
| 存储供给不足 | 该节点存储路径性能低，数据加载受限 | 单节点存储带宽实测 |

★ 慢节点的认定标准（B 级条款）

在同一批次、同一测试条件下，某节点的基准性能低于该批次中位数 10% 以上的，
认定为慢节点。基准测试项包括：单机八卡 NCCL AllReduce Bus BW、gpu_burn 吞吐、
H2D/D2H 带宽、单节点存储读带宽，任一项触发即成立。

上述判据与采购人验收工具链的同批次横向比对口径一致：不低于中位数 95%
判定通过，处于 90% 至 95% 之间判定复测，低于 90% 判定不通过。

| 要求 | 内容 | 供应商应答 |
|---|---|---|
| 按 rank 的每步耗时分布 | 须提供，用于定位性能落后的 rank | |
| 通信等待时长分解 | 须提供，用于区分计算耗时与通信等待 | |
| 定期基准巡检 | 不低于每周一次，全集群执行同一基准并与中位数比对 | |
| 巡检报告 | 须提供予采购人 | |
| `clocks_throttle_reasons` 上报 | 须支持，见 2.7 | |

注：GPU 利用率反映的是有 kernel 在执行的时间占比，降频运行时仍显示 100%。

#### 2.6.4 故障覆盖与自动恢复

自动恢复机制须覆盖下列故障类型，供应商应逐项说明检测手段与处置动作：

1. GPU XID 错误或 ECC 不可纠错——自动隔离该卡与该节点；
2. NCCL 通信超时或 hang——自动识别性能落后的 rank，而非整体重启；
3. InfiniBand / RoCE 链路 down、PFC 风暴；
4. NVLink CRC 错误累积；
5. 节点宕机或掉电；
6. 慢节点——自动从可用资源池中摘除，不再分配新任务；
7. 静默数据损坏（SDC）——计算结果错误但无报错。须说明是否具备定期
   `dcgmi diag -r 3/4` 巡检或数值校验机制。

恢复流程须说明：是否自动从最近 checkpoint 拉起、是否自动替换为热备节点、
是否需人工介入、通知渠道为何。

供应商须提供同规模集群近三个月的真实故障统计，含故障次数、类型分布、
平均恢复时长、掉卡次数与更换耗时、慢节点发现次数与处置耗时、Goodput 实际值。

### 5.2 验收原则

未通过验收的设备不起租、不计费。本条为本项目的前置条件，

采购人已建成离线自动化验收工具链，可在脱网环境及无预装操作系统的裸机上

提供的监控数据。

判定规则：

1. 任一项判定为 FAIL 的，该节点不通过；
2. 无 FAIL 但存在 SKIP（某项无法测得）的，该节点判定为 HOLD，

3. 任一张 GPU 不达标的，整机不通过；
4. 同批次横向比对：单机各项达标但性能低于同批次中位数 10% 以上的，
   判定为 FAIL。

## 第六章 服务等级协议

通用服务等级协议仅考核设备可用性，而本项目的主要损失中，掉卡与慢节点
两类均不体现为设备不可用。故本章按三项独立指标分别考核，
任一指标不达标独立触发赔偿责任，不相互抵扣。

### 6.1 指标与计算方法

| 编号 | 指标 | 承诺值 | 统计周期 |
|---|---|---|---|
| SLA-1 | 集群可用率 | 不低于 99.5% | 自然月 |
| SLA-2 | 有效训练时间占比（Goodput） | 不低于 95% | 自然月 |
| SLA-3 | 慢节点比例 | 不超过 5%，且单台处置不超过 48 小时 | 自然月 |

计算方法如下，该公式将写入合同：

```
可用率 = (在租节点·小时总数 − 不可用节点·小时数) ÷ 在租节点·小时总数

  「不可用」包含：节点宕机、无法登录、掉卡（按 2.6.2 口径，掉任意一卡
  即该节点整机不可用）、网络中断、存储不可读写，以及超出约定窗口的
  计划内维护。

Goodput = (T总 − T中断 − T回退 − T慢节点折算) ÷ T总

  T中断      因平台故障导致训练进程终止至重新拉起的时长
  T回退      自最近 checkpoint 重跑所损失的时长
  T慢节点折算 Σ(慢节点存续时长 × 该节点相对中位数的性能差值百分比)
             例：某节点性能低 15%、存续 100 小时，折算为 15 节点·小时
```

供应商须应答是否接受上述指标与计算方法。如有异议，须提出完整的替代公式。
